# 고등학생 정보보호 수업 준비 계획

상태: Phase 0·1의 G01/G02/G03 웹 구현·검증 완료. 나머지 태스크와 실기기·교실 검증은 미완료다. 목표는 학생이 사이트의 안내만으로 배경→준비→활동→기록→분석→방어→보고서까지 이어 가는 것이다. 실물 장비는 별도로 준비하되, 교사의 추가 구두 설명이나 외부 문서 검색이 필수인 빈틈을 줄인다.

## Phase 실행 순서

**현재: Phase 2 착수 대기. 다음 실행 태스크: B01. Phase 0·1의 웹 입구와 정적 수업/미션 정보만 완료했다.** 아래 Phase는 기존 19개 태스크를 실행하는 순서다. 진행 상태와 완료 체크는 본문의 태스크 체크박스 한 곳에서만 관리하며 Phase용 체크박스를 추가하지 않는다.

### Phase별 파일 소유와 병렬 경계

- Phase 0: 통합 담당자가 상태 표·목록·문구를 소유한다. 기존 학습/워크북 문서의 역할을 합의한 뒤 다음 Phase에 전달한다.
- Phase 1: 수업 입구 담당은 `Base.astro`·학습 입구·`learn.ts`, 미션 입구 담당은 `/lab/` 목록·실제 필요한 공통 소개를 소유해 병렬 가능하다. 공통 CSS·헬퍼·데이터 계약은 통합 담당자 한 명만 수정한다.
- Phase 2: B01 담당은 기존 준비/NFC 경로·NFC 컴포넌트, B02 담당은 Wi-Fi 파일을 소유한다. B02는 B01 인수 후 시작한다. T01 담당은 교사용 문서만 소유해 B01 결과부터 초안을 병행한다.
- Phase 3~4: 각 M 담당자는 본문에 지정한 주제 페이지·주제 전용 코드만 소유한다. 별도 worktree/브랜치에서 배치당 최대 3개를 진행한다. 목록·공통 CSS·저장/CSV·공통 검사 변경은 담당자들이 동시에 쓰지 않고 통합 담당자에게 요청한다.
- Phase 5: T02 담당은 실기기/파일럿 기록, T01 담당은 교사용 수업안 보완을 소유한다. 학생용 수정이 필요하면 해당 주제 담당자에게 돌리고, 바뀐 범위만 다시 확인한다.
- Phase 6: 통합 담당자가 Q01의 검사 증거·동선/상태 일치·수업 인계 목록을 취합한다. 관련 코드 수정은 원래 파일 소유자에게 배정하고 남의 변경을 되돌리지 않는다.

### 반복 진행과 전체 done

T01은 Phase 2의 초안으로 시작해 Phase 3~5에서 실제 지원 미션과 실패 대안을 확장한다. 초안만으로 T01을 체크하지 않는다. 최종 수업안·평가 기준·운영 대안이 선언한 수업 범위를 모두 덮고 파일럿 피드백을 반영했을 때 전체 done으로 본다.

T02의 실기기 관찰은 Phase 2부터 준비된 주제별로 앞당길 수 있다. 교실 파일럿은 해당 웹 ready와 교사용 초안이 있을 때 진행한다. 장비·학생이 없으면 미수행/차단 사유를 기록하며, 다른 주제의 독립적인 웹 개발을 막지 않는다. 기기 미검증 상태에서 대체 경로 파일럿을 통과할 수 있으나 이를 기기 verified로 바꾸지 않는다. T02 체크는 선언한 필수 파일럿 범위의 실제 수행 증거와 본문 인수조건을 갖췄을 때만 한다.

Q01은 매 Phase의 변경 범위에 적용한다. Phase 완료 게이트에는 해당 검사의 명령·범위·결과·소스/환경·스크린샷/오류 증거를 전달한다. Phase 6은 이를 취합해 누락과 새 충돌만 보완하며 전체 검사를 처음부터 반복하는 단계가 아니다. Q01 전체 done은 최종 통합본에 대한 증거 범위가 맞고 미해결 사항·공개 상태·인계 범위가 일치할 때 판정한다.

외부 장비나 학생이 필요한 검증은 계획·개발자 QA·예시 자료로 대신 완료 처리하지 않는다. Phase 0·1 웹 구현의 완료는 기기 verified나 교실 파일럿 passed를 뜻하지 않는다.

## 1. 현재 가능한 것과 남은 일

| 구분 | 현재 근거 | 수업 준비에서 남은 일 |
|---|---|---|
| NFC | 태그 UID·P4~P7 읽기 실행 확인. 기록·CSV·분석·보고서·면접 워크북 있음 | 한 교시 분량·준비 실패·교사용 운영·학생 자력 완주 검증 |
| Wi-Fi RSSI | 수동 입력 웹 워크북 완료. 실제/데모·결측·요약·CSV·보고서 제공 | ESP32-DIV Wi-Fi 실행은 미검증. 교실 도구·시간·대체 경로 확인 |
| 다른 11개 주제 | 목록·생성 장면 이미지·배경 기술노트 있음 | 전용 활동·기록·분석·보고서와 교실 파일럿은 예정 |
| 메뉴 안내 | 메인 8개 묶음·42개 항목 설명과 기존 가이드 연결 | 메뉴가 보이는 것과 기능이 실행되는 것을 구별한 실기기 검증 |

[student-learning-plan.md](student-learning-plan.md) 상단의 ‘구현 완료’는 당시 NFC 중심 계약의 완료 기록이다. 사이트 전체의 교육과정·모든 장비 기능·교실 수업 완료로 읽지 않는다. 메뉴 42개도 실행 가능한 수업 42개라는 뜻이 아니다.

문서 간 기준은 다음과 같이 나눈다. 저장 키·CSV·복구와 기존 학생 데이터 보호는 [workbook-roadmap.md](workbook-roadmap.md) 및 실제 구현 타입을 따른다. 새 문서는 수업 동선·차시·미션의 완료 기준을 맡는다. 충돌하면 기존 데이터와 URL·0~6 기본 경로를 먼저 보존하고, 추가 차시·대체 활동은 이 계획으로 정리한다. 계약 변경이 필요하면 해당 문서와 실행 가능한 체크를 함께 갱신하는 별도 작업으로 남긴다.

### 서로 독립적인 준비도

| 상태 | 올릴 수 있는 근거 | 올리면 안 되는 이유 |
|---|---|---|
| 웹 ready | 빈 기록부터 입력·결측·분석·백업·보고서·접근성 QA 통과 | 생성 이미지·예시 CSV·기기 메뉴 표시만 있음 |
| 기기 verified | 특정 기기·펌웨어·장비·메뉴에서 수행한 실제 관찰과 확인 범위 | 웹 QA 통과, 다른 도구의 측정 성공, 같은 버전 번호 |
| 교실 파일럿 passed | 명시한 학급 규모·시간·장비/대체 경로에서 학생 완주 증거 | 개발자 1인의 클릭 확인, 계획서 작성, 장비만 켜 봄 |

기기 미검증이어도 수동 웹 기록은 완성할 수 있다. 다만 실기기 경로가 막히면 측정한 척 진행하지 않는다. 대체 도구로 실제 관찰하면 도구를 기록하고, 제공 자료를 분석하면 데모/사례 자료임을 유지한다. 파일럿도 ‘기기 경로’와 ‘대체 경로’를 따로 판정한다.

## 2. 학생 입구와 기본 수업

상단 입구는 **수업 시작 / 실습 미션 / 참고 자료** 세 묶음으로 제안한다. 새 이름을 붙이기 위해 기존 URL을 지우거나 이동시키지 않는다.

| 입구 | 연결과 역할 |
|---|---|
| 수업 시작 | `/learn/`에서 목표·준비·0~6 순서를 안내. `/learn/why/`, `/start/`, `/learn/device/` 등 기존 단계로 이동 |
| 실습 미션 | `/lab/`에서 현재 가능한 NFC·Wi-Fi RSSI와 예정 11개, 준비물·예상 시간·선수학습·대체 활동을 비교 |
| 참고 자료 | `/device/`, `/guide/`, `/learn/glossary/`, `/learn/projects/`, `/update/` 유지. 기술노트는 배경 자료이며 실습 시작 버튼과 구별 |

기본 순서는 `0 /learn/why/ → 1 /start/ → 2 /learn/device/ → 3 /learn/nfc/ → 4 /learn/network/ → 5 /learn/security/ → 6 /lab/nfc/`다. 6단계를 일반 미션 목록이나 Wi-Fi로 바꾸지 않는다. 선택 심화는 기본 경로 뒤에 별도 차시 이름으로 붙이며 7·8단계로 기존 번호를 재정의하지 않는다.

다음은 **50분을 기준으로 한 제안**이다. 실측한 수업 시간이 아니며 T02 파일럿에서 조정한다. 학생 수준·장비 수에 따라 나눠 진행할 수 있고, 읽기와 보고서를 한 교시에 모두 끝내도록 강제하지 않는다.

| 차시 | 기존 경로 | 50분 배분 제안 | 차시 종료 산출물 |
|---|---|---|---|
| 기본 A | 0~2 | 생활 문제 8분, 준비 12분, 메뉴/첫 태그 20분, 확인·정리 10분 | 준비표·메뉴 경로·첫 읽기 또는 실패 관찰 |
| 기본 B | 3~5 | 원리 15분, 통신 비교 10분, 위협/방어 15분, 설계 10분 | 통신 단계 설명·위협 모델·탐구 가설 |
| 기본 C | 6 설계·기록 | 복습 5분, 변수/예비 관찰 10분, 반복 관찰 25분, 백업 10분 | 조건별 원자료·실패/결측 메모·관찰/서술 CSV |
| 기본 D | 6 분석·방어 | 복구 5분, 표/그래프 15분, 해석 10분, 방어 비교 15분, 정리 5분 | 표·그래프와 근거/추정/한계·방어 제안 |
| 기본 E | 6 보고서·면접 | 근거 확인 5분, 보고서 20분, 동료 검토 10분, 1분 설명·정리 15분 | 보고서 초안·동료 피드백·면접 설명 |
| 선택 W | Wi-Fi RSSI | 1~2차시. 준비·수동 기록과 분석·방어를 장비 수에 맞춰 분리 | 방별 신호 비교·망 분리의 목적과 한계 |
| 선택 심화 | M01~M11 | 아래 태스크별 1~2차시 초안, 실기기 확인 후 조정 | 해당 주제의 관찰→방어→보고서 묶음 |

핵심 분석은 브라우저 표·그래프만으로 끝낼 수 있어야 한다. Python/Colab은 선택 심화로 연결하고, 계정·로그인·패키지 설치 실패가 기본 보고서 완료나 평가를 막지 않게 한다. NFC의 45시도 예시는 기본 C의 예비 관찰과 파일럿 결과에 맞추며 임의의 성공값으로 채우지 않는다.

## 3. 공통 미션 계약

아래 항목을 학생 페이지에서 찾을 수 있어야 웹 ready 후보가 된다. 모든 항목을 한 거대 스키마나 전용 엔진으로 구현하라는 뜻은 아니다. 기존 헬퍼·폼·표·서술·보고서를 재사용하고, 주제에 필요한 작은 코드만 추가한다.

| 항목 | 미션에 들어갈 내용·인수 기준 |
|---|---|
| 준비물·시간·선수학습 | 장비/추가 부품·작업 장소·개인/모둠 구성, 제안 소요 시간, 관련 0~6 단계와 용어 링크. 장비가 없을 때 쓸 경로도 표시 |
| 메뉴·확인 범위 | 정확한 표시 이름·다음/뒤로 경로·확인 근거. 목록 확인/실행 확인/문서 기준을 분리하고 미확인 버튼 결과를 만들지 않음 |
| 생활 문제·가설 | 왜 궁금한지 한 문장, 답할 질문 하나, 관찰로 비교할 가설. 침입·안전성 판정처럼 측정 범위를 넘는 질문은 좁힘 |
| 변수·반복 | 바꾸는 것/고정하는 것/관찰 결과를 나눔. 반복 수·순서·관찰 시작/종료 기준을 제시하고 표본이 적은 기록도 보존 |
| 관찰 필드 | 입력 출처·시각/조건·대상 별칭·관찰값·메모. 자동 측정이라고 주장하지 않고 연속 기록 때 반복 조건을 불필요하게 초기화하지 않음 |
| 단위·결측 | 실제 표시된 단위만 사용. 신호 못 찾음/미측정/해당 없음과 0·실패를 구별. 동일한 값의 별도 관찰은 별도 행으로 남김 |
| 표·그래프·분석 | 원자료와 n·결측 수, 적절한 요약·축·단위·접근 가능한 표. 수치 없는 설정/문서 비교에는 표를 쓰고 억지 성공률 그래프를 만들지 않음 |
| 해석·한계 | 관찰한 사실/추정/대안 원인을 분리. 결과가 없거나 예상과 달라도 실패 기록과 다음 확인 질문으로 보고서를 완성 |
| 실생활·방어 | 보호할 자산·위협·방어 행동·효과 확인 방법·방어의 한계. 관찰 지표 하나로 공격이나 무해함을 확정하지 않음 |
| 보고서·면접 | 동기→가설→방법→원자료/분석→결과→방어→한계→후속 실험→출처. 실제 한 일만 쓰고, 1분 설명 질문과 답 점검 기준 제공 |
| 성공·중단·실패 대안 | 학습 성공은 유의미한 차이 검출이 아니라 근거 있는 기록/설명. 준비·권한·장비 상태가 불명확하거나 주변 영향이 우려되면 중단. 대체 도구/데모 사례/공책 경로와 복귀 지점 제공 |

모든 실제/데모 구분과 저장 키·CSV·복구 계약은 기존 로드맵을 따른다. NFC `esp32div.nfc.v1`, Wi-Fi `esp32div.lab.wifi-rssi.v1` 및 기존 학생 기록을 보존한다. 새 미션 키는 기존 이름 규칙을 쓰고, 이전 CSV 열을 조용히 바꾸거나 기존 기록에 예시를 자동 삽입하지 않는다.

## 5. 교사·실기기·교실 검증

- [ ] **T01 · P0 · 교사용 수업안과 평가 기준** — 의존성: B01, G01; 심화는 해당 M 태스크 완료 뒤 추가.
  파일 후보: `docs/classroom-teacher-guide.md`, 학생에게 필요한 안내만 기존 학습/미션 페이지에 배치.
  결과물: 차시별 준비·시간표·장비 회전·중단 판단·예상 질문·대체 활동·평가 예시.
  인수: 질문/설계 20%, 기록/복구 25%, 분석/한계 25%, 방어/생활 연결 20%, 자기 설명/출처 10%를 초안으로 파일럿 검토한다. 기대한 성공률이나 장비 수신 성공 자체를 점수로 쓰지 않고, 사실 구분·재현 가능한 기록·실패 대안을 같은 기준으로 평가한다.

- [ ] **T02 · P0 · 실제 기기 검증 기록과 파일럿** — 의존성: T01, 해당 미션의 웹 ready; 우선 NFC/Wi-Fi 다음 M01~M04.
  파일 후보: `docs/device-verification-log.md`, `docs/classroom-pilot-log.md`; 공개 요약은 기존 미션 상태에만 연결.
  결과물: 기기/펌웨어·장비·메뉴·범위·시도/실패·복구·날짜·확인자와 모둠별 소요 시간·막힌 지점·대체 경로 기록.
  인수: 파일럿 전 목표 모둠 수·완주 기준·제안 시간을 정하고 실제 분모와 결과를 보고한다. 안내만으로 저장→복구→보고서를 완성했는지 관찰하며, 실패 대안 경로의 통과도 별도 기록한다. 증거가 없으면 verified/passed를 올리지 않고 미해결 태스크로 남긴다.

실행 순서는 상단 Phase 0~6을 따른다. M11은 Phase 3의 BLE·IR 배치와 함께 진행하고 기존 태스크 의존성은 유지한다. T01은 Phase 2 초안부터 확장하며 T02는 준비된 주제에 한해 Phase 2부터 조기 수행할 수 있다. 검증 대기가 독립 웹 개발을 막지는 않지만 실제 수행 없이 완료로 체크하지 않는다. 병렬 작업은 배치 최대 3개·별도 worktree·주제별 파일 소유를 전제로 하고 공통 변경은 통합 담당자가 처리한다.

## 6. UI·QA와 완료 정의

- [ ] **Q01 · P0 · 관련 변경에 한정한 수업 QA** — 의존성: 검증할 태스크의 결과물.
  파일: 관련 기존 검사 스크립트와 필요한 작은 실행 체크; 새 프레임워크 도입 없음.
  결과물: 명령·범위·변경/환경·결과, 대표 스크린샷 절대 경로, 콘솔 오류 수와 미해결 목록.
  인수: 아래 기준을 만족한 범위만 ready로 올리며, 문서 작성이나 과거 검사 기록만으로 체크하지 않는다.

| 범위 | 확인할 기준·현재 존재하는 명령 |
|---|---|
| 최종 코드 변경 | `npm run typecheck`, `npm run build`, `git diff --check`. 동일 코드·환경의 통과 결과는 재사용하고 관련 수정/실패가 있을 때만 영향 범위를 재실행 |
| NFC 자료/분석 변경 | `npm run check:nfc`. 기존 CSV·학생 기록·데모 분리·보고서와 제공 분석 예제의 실제/결측 처리를 확인 |
| Wi-Fi 변경 | `node scripts/check-wifi-rssi.mjs`; 브라우저 포함 시 `node scripts/check-wifi-rssi.mjs http://127.0.0.1:4331`. 이미 통과한 순수 체크 제외 시 기존 `--browser-only`, 상세 범위는 `--interactions-only` 사용 |
| 메뉴/동선 변경 | `node scripts/check-device-menu.mjs http://127.0.0.1:4331`. 8/42 연결·키보드·JS-off·가이드 앵커를 보존하고 상단 3묶음/새 동선 기대값만 해당 작업에서 보완 |
| 그림/공통 배치 변경 | `node scripts/check-stepper.mjs http://127.0.0.1:4331`. 해당 Stepper의 모든 단계·시나리오·질문 열기에서 그림과 조작부 위치 변동 1px 이내, 반응형·글꼴 준비·모션 줄이기 유지 |
| 학생 화면 | 375/768/1280 양 테마, 공통 배치 변경 시 320도 포함. 테마 토글·긴 한글·빈/오류/결측·데모·가져오기·새로고침·백업·보고서와 실제 다음 행동 확인 |
| 넘침/고정 요소 | 문서 폭뿐 아니라 자식 경계·dt/dd 겹침·고정 메뉴 가림·표 영역을 검사. 현재 Base의 전역 overflow-x:clip에 가려진 이탈도 확인하고, 잘라내기로 오류를 숨기지 않음 |
| 접근성/JS-off | label·단위/오류 연결·키보드/포커스·상태 알림·비색상 구분·그래프 대응 표·장면 alt. JS-off에서도 절차·질문·공책/사례 대안과 다음 링크를 읽음. 콘솔 오류/미처리 예외 0 |

개발 서버는 실제 사용하는 포트로 명령의 origin을 맞춘다. 브라우저는 headless Playwright 기본 Chromium 또는 `~/.agents/bin/test-chromium`만 사용한다. 사용자 Chrome·실제 프로필·CDP 연결·컴퓨터 화면 조작은 금지하며 확인 뒤 자신의 브라우저/서버를 종료한다. 시험 Chromium이 실패하면 실제 Chrome으로 대체하지 않고 원인을 보고한다.

화면 문구·안내·평가지는 모두 자연스러운 한국어로 제공한다. 사용자 원본 사진/메뉴 JPG는 검증 근거로만 읽고 사이트·Git에 새로 노출하지 않는다. 기존 생성 WebP와 비주얼을 유지하며 새 장면이 실제로 필요할 때만 imagegen으로 만든다. 시각 자료를 기기 실행이나 측정값의 근거로 사용하지 않는다.

각 태스크 done에는 산출물 경로·인수조건·관련 검사 증거·남은 기기/수업 한계가 필요하다. 전체 수업 준비 완료는 기본 A~E의 학생 자력 완주, 교사용 운영/평가, 명시된 기기 또는 대체 경로의 파일럿까지 확인했을 때만 선언한다. 선택 심화 11개는 주제별 상태를 따로 유지하며 일부 완료를 전체 완료로 표시하지 않는다. 구현·커밋·푸시·배포는 이후 승인된 작업에서 수행한다.
