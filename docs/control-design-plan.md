# 컨트롤 정리: 단추, 자료 선택 레일, 보고서 도구줄

기준: 9fb6b66. 기존 디자인 시스템(색, 글꼴, 여백 토큰) 안에서 컨트롤만 정리했다. 테마, 내비게이션, 로고는 그대로다.

## 문제 (BEFORE)

- 보고서의 자료 선택(실제/데모)은 검정 알약이었다. 바로 옆 "Markdown 내려받기"도 검정 채움이라 고르기와 실행이 구별되지 않았다.
- 보조 단추(인쇄, 복사)는 회색 채움이었고, 다크에서는 둘 다 흰 채움으로 뒤집혔다.
- 모서리는 단추 10px, 레일 999px로 섞여 있었다. 높이도 48과 44가 섞였고, 지우기 단추는 일반 보조 단추와 같았다.

## 규격 (AFTER)

| 대상 | 규격 |
|---|---|
| 높이 | `--control-h` 44px 하나(단추, 레일 칸) |
| 모서리 | `--radius-control` 8px, 레일 칸 6px |
| 글자 | 단추 16px, 작은 단추와 레일 15px |
| 간격 | 토큰 4, 8, 12, 16, 24 |
| 주요 실행 `.btn` | 숲 초록 채움(`--color-accent`), hover는 `--color-accent-hover` |
| 보조 `.btn--quiet` | 바탕색과 중립 테두리(`--color-control-line`, 바탕 대비 3:1 이상) |
| 지우기 `.btn--danger` | 보조 모양에 오류 색 글자. 지우기 단추 8곳에만 쓴다 |
| 자료와 방식 선택 `.seg` | 한 줄 레일(`--color-paper-3`). 고른 칸은 표면색과 초록 2px 테두리, 굵기로 표시한다 |
| 상태 | hover는 한 단계, active는 1px 눌림, focus는 공통 2px 외곽선. disabled는 `opacity` 0.55와 금지 커서, `disabled` 속성 |

- `.report-bar`: 자료 선택은 왼쪽, 파일 단추는 오른쪽에 같은 축으로 둔다.
  - 폭이 모자라면 자료 선택 다음 줄에 단추가 왼쪽 정렬로 온다. 단추는 내용 폭이다.
  - 보고서 4종(NFC, Wi-Fi, 현장 기록 10개, CSV)에 적용했다.
  - 상태 문구는 도구줄 아래에 두고, 비어 있으면 높이를 차지하지 않는다.
- 단추 이름, id, aria, radio 이름, 저장, CSV, 내려받기, 인쇄, 복사 동작은 그대로다.

## 근거

- **UI-UX Pro Max**: `search.py --design-system`과 `--domain ux/style`을 한 번 실행했다.
  - 쓴 것: 44px 터치, 8px 간격, 단추 그룹마다 주요 실행 하나, 상태 구별, disabled 표시, 지우기 색 분리, 2~4px focus.
  - 추천 팔레트(분홍)와 글꼴은 기존 시스템과 맞지 않아 쓰지 않았다.
- **Hallmark** `flow.md` 컴포넌트 범위, `interaction-and-states.md`, `craft.md` §9, `patterns.md`의 단추 규칙
  - 채운 주요 실행은 하나이고, 보조는 테두리로 둔다.
  - 단추 크기는 하나로 맞추고, disabled는 세 가지로 함께 표시한다.
  - hover는 한 가지 신호만 바꾼다.

  - `.btn`은 약 60곳, `.btn-row`는 27곳, `.seg`는 8곳(자료 선택, 그래프 기준, stepper 방식).

  - 고른 칸과 실행 단추의 색이 다르고, 데스크톱은 한 축, 모바일은 두 줄로 놓인다. 단추는 폭 전체로 늘어나지 않는다.
