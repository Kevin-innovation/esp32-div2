# 14장 면접 준비: 13개 실습 공통

기준: a7b0c41. 모든 실습의 13장 "보고서와 평가" 다음에 14장 "면접 준비"를 둔다. 새 의존성, 서버, 로그인, 외부 API는 없다. 기존 저장 키, CSV 형식, 기록은 바꾸거나 지우지 않는다.

## 1. 공통 14장

- `LabGuide.astro`의 장 목록에 14장을 더한다. 장 목차, scrollspy, `#ch-14`가 자동으로 맞는다.
- `#interview`는 모든 실습에서 14장 수행 영역에 둔다. NFC로 가는 기존 링크(`/lab/nfc/#interview`)가 그대로 14장에 닿는다.
- 13장 끝에 "보고서를 검토했다면 14장" 안내를 둔다. 13장에 있던 1분 설명(`explain`)은 14장으로 옮긴다. 저장 키는 같다.
- 14장은 머리 색과 목차 구분선으로 보고서 다음 단계라는 것을 보여 준다.
- NFC 1장의 A~E 차시 흐름에서 E를 12~14장으로 고친다.

## 2. 미션 질문

- 질문은 `src/lib/workbooks/interview.ts`에 미션마다 6개를 둔다.
  - 주제는 동기, 통신 원리, 변수와 반복, 내 결과와 수치, 보안과 방어, 한계와 현업 응용이다.
  - 각 질문에는 작성 방향, 가상 예시(펼침), 후속 질문 두 갈래가 있다.
  - 후속 질문은 실제 기록이 있을 때와 아직 없을 때로 나뉜다.
- 미션별로 오해하기 쉬운 지점을 질문에 넣는다. 예를 들면 NFC는 UID 읽기와 결제를 구분하고, WPA는 PMF의 역할을 묻는다. BLE는 광고와 페어링을 구분하고, GPS는 원인을 단정하지 않게 한다.
- 예시는 펼쳐야 보인다. 학생이 누를 때만 입력란에 넣고, 이미 쓴 글이 있으면 덮기 전에 묻는다. 실제 측정처럼 자동으로 채우지 않는다.

## 3. 저장과 보고서

- 공통 UI는 `src/components/lab/InterviewPrep.tsx` 하나다. 기존 `NotesEditor`를 다시 쓰고, 값은 각 실습의 기존 서술 저장에 더한다.
  - NFC와 Wi-Fi는 실제와 데모가 서술을 함께 쓴다.
  - 현장 기록 10개와 CSV 가명처리는 실제와 데모를 따로 저장한다.
- 새 키는 `src/lib/interview.ts`의 `IV_KEYS` 한 목록이다. 서술 CSV 허용 목록, 저장 복원, 가져오기와 내보내기가 모두 이 목록을 쓴다.
  - NFC의 기존 면접 답(`q_curiosity`, `q_design`, `q_unexpected`, `q_verify`, `q_limit`)은 같은 키로 14장 질문에 이어진다.
- 내 탐구 요약은 앞 장에서 쓴 질문, 가설, 설계, 결론, 한계와 지금 자료의 기록 수, 계산값을 모은다.
  - 쓰지 않은 칸은 (미작성)으로 둔다. 데모는 가상이라고 표시한다.
- 답변 근거 점검은 학생 체크리스트와 경고만 보인다. 점수와 완료 판정은 없다.
  - 경고 대상은 답이 비었을 때, 실제 기록이 없는데 수치를 근거로 표시했을 때, 수치를 표시했는데 숫자가 없을 때다.
- 1분 설명은 질문, 방법, 결과, 한계, 다음 탐구 다섯 칸으로 쓴다. 이어 붙여 기존 `explain` 칸에 넣는다.
- 면접 준비 Markdown을 내려받을 수 있다. 같은 내용을 각 실습의 전체 보고서 끝에도 붙인다.
- 자바스크립트가 꺼져 있으면 서버에서 그린 질문, 작성 방향, 예시를 그대로 읽는다. 종이에 쓰는 순서도 안내한다.
