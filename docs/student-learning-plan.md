## 목표와 작업 원칙

현재 사이트를 단순 기능 소개에서 학생이 기기를 이해하고 스스로 실험·분석·보고서를 완성하는 한국어 학습 프로젝트로 확장한다. 사용자는 준비물과 기기 화면을 이미 제공했고 개발 완료 후 커밋·푸시까지 승인했다. 추가 기획 승인 대기 없이 구현한다.

구현 담당은 기존 Claude Opus 5.5/high, 메인은 요구사항·계약·이미지 생성·리뷰 담당이다. 하위 에이전트 생성 금지. 다른 작업자의 변경을 덮어쓰지 않는다. 먼저 git status. ponytail full을 적용하고 기존 Astro/TypeScript/React·스타일 토큰·NFC 저장/CSV/보고서 코드를 재사용한다. 서버·로그인·DB·새 UI/애니메이션/검색 라이브러리를 추가하지 않는다. 별도의 추상화나 퀴즈 엔진은 만들지 않는다.

이 문서를 docs/student-learning-plan.md에 복사하고 구현할 경로와 완료 기준을 보완해 개발 문서로 남긴 뒤 바로 구현한다. 장문의 경과 로그 대신 단계별 짧은 요약을 보낸다.

## 최우선 수정: 학생이 보는 이미지는 생성본

사용자가 찍은 IMG_5426.JPG~IMG_5433.JPG는 내용 검증용 참고 자료다. 사이트나 Git에 원본/크롭/리사이즈 사진을 넣지 않는다. 스크린샷 화면을 그대로 웹에 붙이지 않는다. 메인이 built-in image_gen으로 실제 기기처럼 재구성한 8장만 전달한다. 생성된 이미지 파일을 src/assets/learning/의 별도 WebP로 최적화하고 알파/메타데이터를 확인한다. 직접 사진의 배경을 편집하거나 다시 이미지 생성하지 않는다. 기존 홈·기기 페이지의 정리된 제품 이미지는 재사용한다.

새 화면은 장식용 임의 UI가 아니라 아래에서 관찰한 화면의 재구성본이다. 이미지 캡션은 짧게 '실제 화면을 바탕으로 재구성한 학습 이미지'로 명시한다. 이미지 글자가 약간 부정확해도 학생이 틀린 정보를 배우지 않도록 화면 바로 아래 HTML로 정확한 메뉴·값·한글 설명을 제공한다. 핵심 메뉴·숫자가 틀린 이미지는 메인에 보고하고 기술적 사실의 근거로 사용하지 않는다. 숫자를 멋대로 보정하지 않는다.

최종 파일명: main-menu.webp, about.webp, more.webp, nfc-menu.webp, reader-waiting.webp, reader-detected.webp, tag-info.webp, memory-sample.webp. 자리 표시 그림은 남기지 않았다.

## 화면 구성·학습 동선

기존 디자인(한글 Pretendard, 여백, 두 테마, 모바일, 최대 너비/읽기 폭)을 유지한다. 긴 한 페이지에 모든 설명을 쌓지 말고 학습 허브와 짧은 장으로 나눈다. 제안 경로는 아래와 같으며 기존 구조를 재사용할 수 있다.

1. /learn/ — 학생용 시작점: 학습 목표, 준비 완료 상태, 6단계 학습 동선, 예상 산출물. 기존 처음 시작/기능 가이드/실전 탐구와 서로 연결한다.
2. /learn/device/ — 생성 이미지 기반 실제 화면 따라 하기. 메인 메뉴 8개를 선택하면 역할·다음 경로·확인 수준을 보여 준다. More/NFC/Card Reader/Info는 관찰한 실제 경로로 연결한다. 정확한 이미지 핫스폿을 만들기 어렵다면 그림 옆에 같은 배치의 접근 가능한 버튼을 둔다. 가짜 클릭 영역이나 '실제 기기를 원격 제어한다'는 표현은 금지한다. 각 단계에 '누를 것 → 화면 변화 → 확인할 것 → 다음/뒤로'를 적는다.
3. /learn/nfc/ — NFC 통신 원리, 실제 읽기 화면 해석, 바이트/UID/메모리 실습. 기기 동작과 연결되는 단계별 학습 그림/상태 전환을 제공한다.
4. /learn/network/ — 무선 탐색과 데이터 전달의 원리. 수동/능동 Wi-Fi 탐색, AP/단말기, 프레임과 패킷, 캡슐화, BLE 광고와 연결의 차이를 설명한다. 적어도 NFC와 Wi-Fi에 '이전/다음/처음'으로 따라갈 수 있는 작은 단계별 시각화를 제공한다. 실제 캡처가 아닌 원리 설명용 모형이라고 표시하고 자동 재생·과한 애니메이션은 피한다.
5. /learn/glossary/ — 검색·분류 가능한 한글 용어 사전. 기존 가이드 검색에도 새 학습 페이지와 주요 용어를 연결한다. 화면의 영문 원문은 유지하고 한글 뜻을 병기한다.
6. 기존 /lab/nfc/ — 실제 기기로 시작하는 탐구 워크북으로 상세화. 학습 장에서 워크북으로, 워크북의 어려운 개념에서 해당 장/용어로 바로 이동한다.

URL은 간결하게 유지하고 현재 기존 링크·앵커를 깨지 않는다. 상단에는 학습 입구 하나만 추가하고 학습 하위 목차로 분류해 메뉴가 과밀해지지 않게 한다. 학습 화면은 모든 핵심 내용이 스크립트 없이도 읽혀야 하며 상호작용에만 React를 쓴다.

## 학생에게 반드시 설명할 내용

### A. 기기와 화면 읽기

메인 8개 버튼의 쉬운 역할, 실제 메뉴명과 한글 풀이, More의 하위 분류, 실제 확인된 NFC의 전체 경로, About의 버전 세 가지 차이를 설명한다. Mode SCAN/OK, Waiting for tag, Tag detected, Reader IC, Protocol, UID, Detected type, Variant, Info, Cancel/Exit/Back/Prev/Next를 모두 번역한다. PN532의 0x32010607은 리더 칩 버전 정보 표시이며 기기 전체 펌웨어 1.7.2와 구별한다. 상단 CHG/BAT/배터리 %는 UI 표시로만 설명하고 적색 SD 아이콘만 보고 고장·삽입 상태를 단정하지 않는다.

NFC 메뉴의 Card Clone/Erase/Dump/Decode Access/Jam Reader/Tag Disrupt/Disrupt Emulate는 각각 목적과 읽기/쓰기/삭제/방해 차이를 쉬운 말로 설명한다. 실험 프로젝트는 Card Reader에 한정한다. 지원하는 태그만 복제할 수 있고 UID 읽기나 저장이 결제 가능한 카드 복제와 같지 않음을 설명한다. 교란/자격 증명 수집/실제 결제카드 복제/무선 키보드 주입의 실행 레시피나 공격 코드는 추가하지 않는다. 불필요한 반복 경고 대신 해당 기능 설명에서 영향과 허가 조건을 짧게 전달한다.

### B. NFC: 무엇이 오가는가

13.56MHz 리더 자기장 → 수동 태그가 유도 결합으로 에너지를 얻음 → 탐색 요청/태그 응답 → 충돌 방지와 선택 → UID 확인 → 메모리 READ 요청/응답 → 화면 표시를 구분한다. 태그가 Wi-Fi에 접속하거나 인터넷으로 UID를 보내는 과정이 아니다. 리더의 명령·태그 응답은 이 실험에서 ISO14443A 프레임이며 IP 패킷과 구별한다. 태그 응답의 부하 변조, 안테나 방향·위치·거리·금속에 따라 결합이 달라지는 원리를 고등학생도 이해하게 설명한다.

REQA/WUPA, ATQA, 충돌 방지, SELECT, SAK, READ는 원리 수준에서 설명한다. 사진에는 전체 무선 캡처가 없으므로 실제 명령 순서와 바이트를 캡처한 것처럼 꾸미지 않는다. UID를 읽었다고 사용자 메모리를 모두 읽은 것은 아니다. UID는 식별값이지 암호키·계좌·비밀번호가 아니다.

실제 UID 53 01 05 D0 43 00 01을 예로 7바이트=14자리 16진수, 1바이트=8비트, 페이지당 4바이트를 설명한다. P4~P7은 4페이지×4=16바이트 샘플, 00도 정상 데이터 값이라는 것을 보여 준다. 예를 들어 0x01=00000001을 정확히 풀어 준다. 이 메모리 샘플을 암호키/결제 정보/전체 데이터라고 해석하지 않는다.

NTAG213의 공식 144바이트 사양과 기기에서 표시한 pages 4–15(12페이지라면 48바이트)의 차이를 학습 질문으로 삼는다. 화면의 범용 분류일 가능성은 있으나 원인은 미확인이다. 판매 표기와 펌웨어 판정, 실측 결과를 구분하며 가짜 태그·고장·정품이라고 단정하지 않는다. 샘플 16바이트로 전체 용량을 판정할 수 없음을 적는다.

### C. Wi-Fi·네트워크: 어떻게 탐색하고 패킷이 전달되는가

AP(공유기)/단말기/스캔 장비를 분리한다. 수동 탐색은 AP의 Beacon을 듣고, 능동 탐색은 Probe Request를 보내 Probe Response를 받는 일반 원리를 설명한다. 스캔이 항상 수동이라는 표현 금지. 실제 MK 펌웨어의 스캔 모드는 아직 확인하지 못했다고 구분한다. SSID/BSSID/MAC/채널/RSSI/dBm을 목록 예시와 함께 읽는다. RSSI의 -40dBm이 -70dBm보다 강하다는 예와 거리·벽·방향·혼잡이 값에 영향을 주는 것을 설명한다. RSSI 하나로 정확한 거리나 도청 가능성을 판정하지 않는다.

연결 후 웹 요청의 일반 흐름은 연결/주소 설정(DHCP 등) → DNS → TCP/TLS → HTTPS 요청/응답으로 설명하되 고정 IP/DNS 캐시/HTTP3 같은 예외가 있어 모든 통신이 이 순서를 그대로 따르지는 않는다고 짧게 밝힌다. 애플리케이션 데이터→전송계층→IP 패킷→Wi-Fi 프레임→전파를 계층 그림으로 보여 준다. 헤더/페이로드/주소/암호화 구간을 나눠 '패킷 모니터=남의 HTTPS 내용을 전부 읽기'가 아님을 설명한다. ARP는 로컬 링크의 IP-MAC 관계, NAT는 별도 개념으로 설명한다.

2.4GHz 에너지 스캐너는 주변 신호 에너지를 보는 기능이지 프로토콜/메시지를 자동 해독하는 기능이라고 단정하지 않는다. ESP32-S3 내장 Wi-Fi는 2.4GHz이며 모든 5GHz Wi-Fi를 지원한다고 쓰지 않는다. BLE 광고/스캔/연결은 서로 다르고 ESP32-S3의 내장 BLE를 Classic Bluetooth 전부와 혼동하지 않는다. 프로토콜 별 실제 기능과 하드웨어 지원은 공식 근거로 확인한다.

### D. 용어 사전

사이트 학습에 쓰이는 주요 용어를 약 60~80개 이상 충분히 해설한다. 각 항목은 한글명/영문·약어/쉬운 뜻/실제 예/혼동하기 쉬운 점으로 구성하고 관련 학습 위치와 연결한다. 사전 검색은 대소문자·띄어쓰기·한글/영문 별칭을 지원한다.

최소 범위: NFC, RFID, 리더, 태그, 수동/능동 태그, 주파수, Hz/MHz/GHz, 안테나, 자기장, 유도 결합, 부하 변조, 프로토콜, ISO14443A, PN532, UID, NTAG213, Ultralight, ATQA, SAK, REQA, WUPA, SELECT, READ, 충돌 방지, CRC, bit/byte/hex/page, NDEF, TLV, 메모리 샘플; Wi-Fi, AP, 단말기, SSID, BSSID, MAC, IP, RSSI, dBm, 채널, 대역폭, Beacon, Probe Request/Response, 프레임, 패킷, 헤더, 페이로드, 스캔, 스니핑, PCAP, DHCP, DNS, ARP, NAT, TCP, UDP, HTTP/HTTPS, TLS, 암호화, 인증/인가, BLE, 광고 패킷; 독립/종속/통제 변수, 반복, 표본, 인식률, 가설, 오차, 재현성, CSV. 필요 용어를 추가하되 단순 영한 단어 목록으로 끝내지 않는다.

### E. 실전 탐구와 보고서

준비 완료 상태(기기·구매 태그·실제 읽기 확인)를 반영하고 기존 리더 후보 나열을 이 장비 중심으로 바꾼다. 실험용 태그 한 개, 기기, 자/고정대/테이프, 지갑/가방, 기록 도구가 준비물이다. 한 태그를 쓰고 여러 태그/금속을 처음부터 섞지 않는다.

매 시도는 태그를 떼고 Card Reader를 다시 열어 Waiting for tag 상태에서 시작한다. 기존 OK 화면이 남은 것을 재인식 성공으로 세지 않는다. 재진입 실제 버튼은 확인된 Exit→Card Reader 경로를 사용하며 검증하지 않은 자동 반복 기능을 만들지 않는다. 기준 예: 5초 이내 새 Tag detected+예상 UID가 표시되면 성공. 시간은 사람이 재며 웹이 자동 측정한다고 하지 않는다. 실패도 기록하며 조건 순서를 번갈아 배치하는 이유도 설명한다.

최초 예비 실험: 안정적인 태그 위치를 찾고 표시. 거리 측정 기준은 알 수 없는 내부 코일 위치가 아니라 '기기 뒷면 바깥 표면과 태그 표면 사이' 등 재현 가능한 기준으로 정한다. 0cm는 외부 표면 접촉이다. 지갑/가방의 외피 사이 거리와 안쪽 태그까지 거리가 다름을 반드시 적는다. 실생활 넣기 실험의 전체 효과와, 재질 자체만의 효과를 구별한다. 재질만 비교하려면 태그 위치·총거리·방향을 유지해야 한다.

기본 설계 예: 단독/지갑/가방×0/1/2cm×5회=45시도. 장비 예비 결과에 따라 거리를 조정하되 예시 수치를 측정값으로 넣지 않는다. 조건/거리/방향/내용물 가운데 한 변수부터 비교, 재질·두께·금속·방향·위치를 한꺼번에 바꾸지 않는다. 반복이 적은 0%/100%를 절대적 보장으로 해석하지 않는다. 동일 UID 재검출 여부, 저장 오류/초기화 실수와 RF 인식 실패를 나눠 생각한다.

기존 기록·그래프·CSV·데모 분리·저장 오류 보호·보고서·면접 기능을 유지한다. 기존 학생 localStorage를 초기화/덮어쓰기하거나 실제 기록에 예제를 자동 주입하지 않는다. 입력 칸은 기존 계획/통제/리더/태그/해석 필드를 최대한 재사용한다.

Python에는 준비/CSV 파일 위치/실행 명령/결과 PNG 위치와 read_csv, UTF-8 BOM, groupby, count/sum, 성공 0/1, 비율 계산, 그래프 축·범례 읽는 법을 설명한다. 원본 CSV 열과 코드가 계속 맞아야 한다. 학생이 해볼 변경 과제(반복 횟수/묶는 기준/거리별 비교)와 결과 예측 질문을 제공한다. 기존 분석 코드가 바뀌지 않으면 Python 실행을 반복하지 않는다.

보고서는 탐구 동기→가설→방법→실측 데이터→그래프→결과 해석→예상 밖 결과와 추가 실험→태그/결제 보안 비교→한계→후속 질문→출처를 학생이 자기 말로 쓰도록 한다. 자기소개서/면접은 실제로 한 것만 설명하게 질문·답변 구조를 제공하며 성과/결론/경험을 지어내지 않는다. 각 학습 장에 2~3개 '생각해 보기/답 확인' 질문과 짧은 정답 해설을 native details 등으로 제공한다.
