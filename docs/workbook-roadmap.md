# 실험 워크북 확장 실행 계약

상태: **Phase 6 통합 완료(실기기·교실 파일럿 보류)**. NFC·선택 Wi-Fi RSSI·심화 11개를 포함한 총 13개 웹 워크북의 구현과 관련 QA를 완료했으며 예정 항목은 0개다. 기기 확인은 기존 NFC UID·P4~P7 범위만 유지하고, 나머지 기능과 모든 교실 파일럿은 미검증이다. 아래 개발 계약·1차 구현의 검사 기록은 당시 상태를 보존하며, 현재 인계는 문서 끝에서 별도로 정리한다.

## 1. 현황과 변경 경계

| 구분 | 확인한 것 | 확인하지 못한 것 |
|---|---|---|
| 기기 | 부팅·메인·More·NFC 메뉴, PN532 표시, 구매 태그의 UID 및 P4~P7 읽기 | Wi-Fi/BLE/IR/Sub-GHz/2.4GHz/GPS 실행, NFC의 다른 기능, 펌웨어 서명 검증 지원 |
| 웹 | NFC·Wi-Fi RSSI·심화 11개 전용 기록/분석·실제/데모 분리·CSV/보고서와 대체 활동. NFC Colab·선택 로컬 파일 해시 포함 | 기기 자동 연결·측정, 웹 QA를 넘어선 실기기 실행·교실 완주 |
| 목록 | NFC 포함 13개 사용 가능 워크북의 시작 링크·준비물·대체 활동·준비도. 예정 0개 | 이미지에 그려진 장비·화면을 근거로 한 기능 지원 또는 취약점 판정 |

웹의 `사용 가능`과 기기의 `실행 확인`은 별개다. 수동 기록 UI가 완성되어도 실제 기기 미검증 표시는 유지한다. 기기 확인 상태를 올리려면 담당자가 준비물, 실제 메뉴, 펌웨어 표기, 수행 조건, 관찰 결과와 확인 범위를 기록해야 한다. 읽기 한 번의 성공을 전체 기능 검증으로 확대하지 않는다.

### G01 준비도 근거와 Phase 0·1 범위(당시 기록 보존)

NFC의 기기 확인은 사용자 관찰 화면의 UID·P4~P7 읽기 범위다. Wi-Fi RSSI는 수동 입력·집계·CSV·보고서 웹 검사만 완료했고 ESP32-DIV의 실제 Wi-Fi 실행은 미검증이다. 나머지 11개는 웹 개발 예정이며 모든 주제의 교실 파일럿은 미검증이다. 메뉴 8/42의 표시·설명은 `src/data/learn.ts`의 지도와 기존 가이드가 근거이며 기능 실행 검증으로 승격하지 않는다. Skimmer Detect의 BLE 분류에는 기존 가이드·촬영 순서라는 경계가 있다.

`src/data/classroom.ts`는 위 세 가지 상태와 시간/준비/선수학습/대체 활동을 위한 정적 수업 정보만 추가한다. 기존 `nfc.ts`·`workbook.ts`·저장/CSV·실습 컴포넌트는 이번 Phase에서 변경하지 않았다. 수업 시작/실습 미션/참고 자료 입구와 기본 A~E·선택 W 안내는 [교실 준비 계획](classroom-readiness-plan.md)의 G01/G02/G03 완료 범위다. 다음은 Phase 2 B01이며 실기기/교실 검증이나 전체 수업 완주 완료를 뜻하지 않는다.

검사 근거는 `scripts/check-classroom.mjs`의 관련 웹 QA 1505개 체크·콘솔 0과 `/tmp/esp32-classroom-qa/result.txt`에 남겼다. 기존 학생 저장값, 0~6 경로와 NFC 앵커를 확인했고 동일한 실습/CSV 전체 검사는 반복하지 않았다. 기존 구현 증거는 아래 기록을 유지한다.

기존 동작을 동결한다: `/lab/nfc/`, `#report`, `#interview`, 기존 저장 키·CSV·실제/데모 구분·입력값·백업 보호. `src/data/learn.ts`의 0~6 순서와 6단계 `/lab/nfc/`도 유지한다. 신규 워크북은 `/lab/`에서 선택하는 후속 활동이다. 기기 관찰 근거와 NFC 수업 설명은 [학생 학습 계획](student-learning-plan.md)의 해당 절을 재사용한다.

### 활동 범위

- 자신의 공유기·이어폰·실험 태그·리모컨·별도 실험 송신기와 준비한 파일을 대상으로 관찰한다. 주변 기기의 식별자는 수집·공유 산출물에서 제외한다.
- 신호 방해, 패킷 주입, 가짜 AP 생성, 실제 카드 복제, 실제 출입·차량 리모컨 재전송, GPS 위조 신호 송신 절차는 구현하지 않는다. 고정/롤링 코드와 위조 위험은 관찰·문서 비교·교차 확인으로 배운다.
- 사이트는 학생이 입력한 값만 분석한다. 미측정값, 가상 값, 문서에서 읽은 설정, 실제로 관찰한 값을 구분한다. RSSI·AP 수·에너지·GPS 값 하나로 공격, 정확한 거리, 안전 여부를 판정하지 않는다.
- 서버·로그인·DB·자동 기기 제어·새 UI/스키마/테스트 라이브러리를 추가하지 않는다. 공통 입력·CSV·보고서 부분만 재사용하고, 주제별 판단은 작은 순수 함수와 정적 수업 내용으로 둔다.

## 2. 공통 데이터 계약

아래는 신규 워크북의 의미와 호환성 계약이다. 실제 타입의 단일 원본은 코어 담당자가 정한 타입 파일에 두고 UI·주제 담당자가 복제하지 않는다. 구현 중 필드 이름을 조정하면 이 문서와 첫 CSV 예제를 함께 맞춘다. 기존 NFC `Trial`을 이 계약으로 강제 변환하지 않는다.

### WorkbookDefinition

| 항목 | 계약 |
|---|---|
| `id` | URL·저장·CSV에 쓰는 안정된 slug. 변경은 데이터 이관 작업으로 취급한다. |
| `title`, `question` | 학생이 관찰할 생활 문제와 탐구 질문. 보안 질문·준비물·절차는 해당 페이지의 정적 콘텐츠로 둔다. |
| `availability` | `planned` 또는 `ready`. 입력·분석·보고서의 해당 주제 QA가 끝나야 `ready`로 바꾼다. |
| `deviceVerification` | `unverified` 또는 `verified`. 소프트웨어 완료와 독립적으로 관리하고, verified에는 확인 범위·근거 경로를 붙인다. 신규 12개는 unverified로 시작한다. |
| `fields` | 순서가 있는 입력 필드 목록: 안정된 key, 한글 label, number/text/choice/boolean 타입, 필요 시 단위·허용값·범위·nullable. 중첩 객체나 임의 수식 언어는 받지 않는다. |
| `noteKeys` | 허용하는 탐구 서술 키. 공통 동기·가설·설계·해석·결론·예상 밖 결과·추가 실험·보안·한계·면접 항목을 재사용한다. |
| `metrics`, `sources` | 출력할 집계 이름·단위와 근거 링크. 집계는 해당 주제의 명시적 함수로 구현하며 문자열을 실행하지 않는다. |

상태 저장용 구조는 `{ schemaVersion: 1, workbookId, observations, notes }`다. `view`, 오류 메시지, 가져오기 미리보기 등 일시적인 UI 상태는 영구 데이터와 분리한다.

### Observation

| 항목 | 계약 |
|---|---|
| `id` | 입력 시 생성해 백업에 보존하는 식별자. 기기 UID/MAC와 무관하다. |
| `dataType` | `real` 또는 `demo`. 데모는 명시적으로 불러올 때만 생긴다. 자동으로 실제 기록에 섞지 않는다. |
| `trial` | 조건별 회차인 1 이상의 정수. CSV 왕복에서 번호를 재계산하지 않는다. |
| `condition` | 비교 조건의 이름. Wi-Fi RSSI에서는 장소 이름이다. |
| `values` | Definition에 선언한 key만 허용하는 문자열·유한 숫자·boolean·null 값. null은 미측정/해당 없음이며 0이나 실패로 치환하지 않는다. |
| `note` | 학생이 눈으로 본 상황·이상 결과. HTML로 해석하지 않는다. |

동일한 값이 반복 측정되어도 새 입력은 각각 별도 관찰이다. 내용이 같다는 이유로 합치지 않는다. 가져오기에서는 같은 id와 같은 내용만 재수입으로 건너뛴다. 같은 id에 다른 내용이 있으면 충돌 행을 표시하고 자동 덮어쓰기를 하지 않는다. 신규 CSV의 id를 잃은 기록에 NFC의 내용 기반 중복 제거를 그대로 적용하지 않는다.

### 저장·복구

- 키 규칙은 `esp32div.lab.<slug>.v1`; 첫 주제는 **`esp32div.lab.wifi-rssi.v1`**로 동결한다. 슬러그별 실제/데모·서술은 이 키 안에서 분리한다. NFC의 **`esp32div.nfc.v1`은 변경·삭제·자동 이관하지 않는다.** 테마 키도 건드리지 않는다.
- localStorage 읽기·쓰기 실패는 사용자에게 저장되지 않았음을 알리고 현재 입력과 CSV 내보내기를 유지한다. 손상·미지원 버전 원본은 덮어쓰기 전에 별도 보존한다. 보존도 실패하면 자동 쓰기를 막고 원본을 지킨다. 기존 `store.ts`의 원칙을 재사용한다.
- 다른 워크북·버전의 자료는 미리보기에서 거부한다. 가져오기는 행 수·문제 행·추가/교체 결과를 보여 준 뒤 적용한다. 교체·전체 삭제에는 실제 영향 건수와 백업 안내를 제공한다. 한 행 삭제는 되돌릴 수 있어야 한다.
- 기본 제한은 현재 NFC와 같은 1MiB CSV·5,000행, 조건 40자·관찰 500자·서술 항목 4,000자다. 전체 저장 행 제한과 필드별 추가 제한도 코어에서 한 번 정의한다. 새 제한이 필요하면 학생 기록을 조용히 자르지 않는다.

### CSV 호환

- 기존 NFC 기록 CSV `trial,condition,contents,distance_cm,orientation,success,note,data_type`와 서술 CSV `field,value`는 그대로 유지한다. 신규 워크북은 이를 자신의 자료로 오인하지 않고 `/lab/nfc/`에서 열도록 안내한다. NFC도 신규 워크북 CSV를 NFC 기록으로 강제 변환하지 않는다.
- 신규 기록 CSV v1은 `schema_version,workbook_id,observation_id,data_type,trial,condition,note` 뒤에 `fields`의 key를 선언 순서대로 붙인다. 각 행에 같은 버전·workbook_id를 기록한다. 혼합 주제·버전, 중복 헤더, 알 수 없는 필드, 타입 오류는 행/열과 함께 알린다.
- 신규 서술 CSV는 `schema_version,workbook_id,field,value`; field는 noteKeys만 받는다. 관찰 CSV와 서술 CSV를 따로 내려받으며, 양쪽을 복구해야 완전한 탐구 백업이라는 점을 설명한다.
- UTF-8 BOM, CRLF, 따옴표·쉼표·줄바꿈 왕복과 문자열 수식 주입 방지를 유지한다. 숫자 RSSI의 음수는 숫자로 내보낸다. nullable 숫자의 빈 칸을 `Number('')`로 0 처리하지 않는다. boolean은 0/1, null은 빈 칸으로 내보내며 필드 타입으로 복원한다.
- 기존 `parseCsv`, `csvCell`, `uncsvText`를 재사용한다. 공통 위치로 옮길 필요가 있을 때만 코어 담당자가 NFC 회귀 검사를 포함해 분리한다. CSV 헤더·브라우저 집계·Python/노트북 예제는 같은 필드와 결측 규칙을 사용한다.

### 가명 처리

1차 Wi-Fi 입력은 공유기 별칭 `AP A`처럼 식별에 충분한 이름만 받는다. SSID·BSSID·UID 원문과 주소·학교/집 상세 위치는 기본 입력·CSV·보고서에 요구하지 않는다. 원문과 별칭의 대응표가 필요하면 학생이 별도 비공개 기록으로 관리한다.

후속 CSV 가명 처리 활동은 원본 파일을 자동 저장하거나 덮어쓰지 않는다. 학생이 선택한 열을 메모리에서 `태그 A`, `AP A`처럼 바꾸고 새 파일을 내려받는다. 동일 작업 안에서 같은 식별자는 같은 별칭을 쓰며, 대응표는 공유 CSV·보고서에 넣지 않는다. 단순 무염 해시를 익명화라고 부르지 않는다. 자유 서술·시간·장소 조합에 재식별 단서가 남는지 내보내기 미리보기에서 점검한다.

## 3. 1차 납품: Wi-Fi RSSI 수직 슬라이스(당시 계약)

목표 URL은 `/lab/wifi-rssi/`. 자신의 공유기를 같은 위치·높이·방향·관찰 시간 조건에서 장소별로 비교하고, 신호 음영과 침입 추정을 구분하는 보고서를 만든다. 실제 MK 펌웨어의 탐색 방식·표시 항목은 미확인이므로 확인하지 않은 메뉴 세부 동작을 지어내지 않는다. 필요한 값을 볼 수 없으면 미측정으로 남기고 대체 측정 수단을 명시한다.

### 입력·분석 범위

- 공통 condition은 장소, values는 대상 공유기 별칭·관찰됨/관찰 안 됨/미확인 상태·RSSI(dBm, nullable)·채널(nullable)이다. 필요 시 시간대 같은 통제 정보는 서술로 시작한다. 실제 화면 확인 전 주파수 대역·패킷 수·응답 시간 자동 측정 칸을 만들지 않는다.
- 관찰됨에는 유효한 RSSI가 필요하고, 관찰 안 됨/미확인은 RSSI null로 기록한다. 허용 숫자 범위는 Definition에 명시하되 앱 입력 범위를 기기 사양으로 설명하지 않는다. 빈 칸·NaN·Infinity·양의 RSSI 등 잘못된 입력은 저장 전 이유를 표시한다.
- 예비 관찰로 장소 3곳을 고르고 장소별 5회, 총 15회를 권장한다. 반복 수가 적어도 기록·내보내기는 막지 않고 표본 수를 표시한다. 장소 순서는 번갈아 배치하고 공유기·대상 별칭·방향·관찰 방법을 고정한다.
- 장소별 유효 RSSI의 n·중앙값·최솟값·최댓값과 미관찰/미확인 수를 보인다. null은 계산에서 제외한다. -40dBm은 -70dBm보다 강하다는 방향을 축·설명에 맞춘다. 정확한 거리·속도·도청 가능성·침입 여부로 환산하지 않는다.
- 그림에는 대응하는 접근 가능한 표가 있다. 데이터가 없거나 유효한 RSSI가 전부 null이면 수치 0·NaN·허위 그래프 대신 빈 상태와 이유를 보여 준다.

### 인수 기준

## 4. 파일 소유와 후속 11개 태스크(구현 당시 계약)

코어·첫 슬라이스를 먼저 직렬로 통합한다. 공통 타입/CSV/저장/보고서 렌더러의 경로는 코어 담당자가 확정한다. 제안 위치는 `src/lib/workbook.ts`, `src/components/lab/WorkbookLab.tsx` 및 공통 상태 모듈이다. 이 경로들은 **코어 담당자 한 명만 수정**한다. NFC `nfc.ts`·`NfcLab.tsx`·`store.ts`는 기본 수정 금지다. 필요한 재사용 경계 변경은 별도 작은 계약으로 처리한다.

후속 담당자는 주제 slug에 대응하는 `src/data/workbooks/<slug>.ts`와 `src/pages/lab/<slug>.astro`만 소유한다. 기존 데이터 파일 체계를 코어가 다르게 정하면 동일한 주제별 소유 원칙으로 맞춘다. 별도 로직 파일은 그 주제의 비자명한 집계가 필요할 때만 추가한다. 목록·공통 CSS·내비게이션·공통 검사 파일·이미지 매핑은 통합 담당자가 수정한다. 주제 담당자는 공통 변경 요청과 검사 사례만 전달한다.

모든 태스크의 공통 납품물은 해당 주제의 설계, 실제/데모 기록, 적절한 표·분석, CSV와 분석 예제, 해석·보안 비교, 보고서·면접 질문이다. 수치가 맞지 않는 체크리스트 주제에 성공률 그래프를 억지로 붙이지 않는다. 아래 slug는 예정 카드 순서에 대응하는 신규 워크북 식별자 제안이며 기존 기술노트 앵커를 바꾸지 않는다.

| 순서·소유 slug | 독립 작업과 준비물 | 기록·분석·학생 산출물 및 고유 done |

### 권장 통합 순서

1. 코어 계약 확정→Wi-Fi RSSI 완주→검사/파일 경계 동결. 첫 슬라이스가 실패한 상태에서 11개 페이지를 복제하지 않는다.
2. Wi-Fi 묶음: `ssid-map`, `wpa-pmf`, `channel`을 독립 제작한다.
3. BLE/환경 묶음: `ble-ad`, `ble-pair`, `interference`.
4. 수신 관찰 묶음: `ir`, `subghz`, `gps`.
5. 파일/데이터 묶음: `firmware`, `csv`. 기기 없이 PC로 검증할 수 있어 앞 묶음과 교환 가능하다.

병렬 후보는 한 번에 최대 3개다. 실제 동시 쓰기는 작업별 별도 worktree/브랜치와 명시적 파일 소유로 분리한다. 같은 공통 파일을 동시에 고치지 않는다. 공통 API를 바꿔야 하면 해당 태스크만 멈추고 코어 담당자가 먼저 통합한다. 장비가 없는 태스크도 정적 수업·가상 자료 기반 UI 검사는 진행할 수 있으나, 장비 실측 완료로 표시하거나 실제 결과를 만들어 내지 않는다.

## 5. QA와 공개 기준

- **순수 로직:** 기존 Node 실행 방식을 사용해 신규 계약·음수/결측 집계·CSV 왕복·중복/충돌·위험 문자열을 검사하는 실행 가능한 체크 하나를 남긴다. 주제별 비자명한 집계만 관련 사례를 추가한다. 새 테스트 프레임워크는 만들지 않는다.
- **NFC 회귀:** 신규 키·가져오기·삭제 후 기존 NFC 저장값의 동일성을 확인한다. NFC 로직이나 공유 CSV 함수를 실제로 바꾼 경우에만 기존 `npm run check:nfc`를 실행한다. 변경 없는 NFC/Python/사이트 전체 검사를 안심용으로 반복하지 않는다.
- **최종 정적 검사:** 해당 납품 변경 후 `npm run typecheck`, `npm run build`, `git diff --check`. 검증된 동일 코드·환경은 재사용하고 실패·추가 변경에 영향받은 범위만 다시 검사한다.
- **브라우저:** headless Playwright 기본 Chromium 또는 `~/.agents/bin/test-chromium`만 사용한다. 사용자 Chrome·실제 프로필·기존 브라우저 연결·컴퓨터 화면 조작은 사용하지 않는다. 소유한 브라우저/서버를 확인 후 종료한다.
- **반응형:** 신규 페이지 375/768/1280 양 테마를 기본으로, 공통 배치 변경이 있으면 320px도 포함한다. 문서 가로 넘침, 카드/필드 이탈, dt/dd 겹침, 태그 잘림, 고정 메뉴 가림이 없어야 한다. 표가 필요한 가로 스크롤은 라벨·키보드 접근 가능한 표 영역 안에만 둔다. 부모의 overflow:hidden으로 결함을 숨기지 않는다.
- **접근성:** 모든 입력의 label·단위·오류 연결, 라디오/버튼 키보드 조작, 보이는 포커스, 결과 알림의 role/status를 확인한다. 정보는 색만으로 구분하지 않는다. 그래프를 설명하는 표와 이미지의 장면 alt를 제공한다. 기존 이미지 lazy/async·크기 예약과 카드 간격 40px를 보존한다.
- **스크립트 없음:** 준비물·절차·관찰 기준·보안 설명·보고서 작성 질문은 읽을 수 있어야 한다. 기록·그래프·내보내기의 JS 필요 안내와 공책에 옮길 항목을 제공한다. 동작하지 않는 컨트롤을 실제 측정 도구처럼 보여 주지 않는다.
- **오류 경로:** 저장 차단·손상/다른 버전 자료·CSV 잘못된 행·전체 결측·긴 한글/식별자·빈 기록을 포함한다. 실제/데모 분리와 재방문 복구도 확인한다. 콘솔 오류와 처리되지 않은 예외는 0이어야 한다.
- **증거:** 명령·검사 범위·결과·통과 당시 변경/환경, 대표 모바일·데스크톱 양 테마 스크린샷의 절대 경로와 콘솔 오류 수를 한 번 보고한다. 기기 검증은 웹 QA와 따로 보고한다. 공개 상태 전환·커밋·푸시·배포는 해당 작업에서 받은 사용자 승인 범위 안에서만 한다.

워크북 소프트웨어의 done은 위 흐름과 QA가 동작하는 상태다. 개별 학생의 실험 done, 실제 장비의 검증 done, 해당 기술의 보안성 입증은 서로 대체하지 않는다.

## 1차 구현 기록: Wi-Fi RSSI

첫 구현은 `src/lib/workbook.ts`의 `WifiObservation`과 `src/components/lab/WifiRssiLab.tsx`를 사용하는 작은 수직 슬라이스다. 후속 주제를 미리 처리하는 범용 폼/수식 엔진이나 새 의존성은 만들지 않았다. `WorkbookDefinition` 등 위 공통 계약은 후속 확장 기준으로 남기며, 아직 모든 주제의 타입을 구현했다고 주장하지 않는다.

- 실제 필드: id·실제/데모·회차·방(room)·추가 조건(condition)·거리(m)·관찰 상태·nullable RSSI·nullable 채널·관찰 시각·SSID/BSSID 별칭·메모. 실제 식별자는 요구하지 않는다. 같은 값의 별도 입력은 별도 id/회차로 보존하고, 같은 id·내용의 재수입만 생략한다. id 충돌은 건너뛰며 건수를 알린다.
- 저장 키는 `esp32div.lab.wifi-rssi.v1`, 내용은 `{schemaVersion:1, workbookId:'wifi-rssi', observations, notes}`다. 최초 개발본의 버전 없는 저장 객체도 검증해 읽는다. 손상·중복 id·지원하지 않는 버전/주제는 원본을 `.broken.<시각>` 키에 보존하고 경고한다. 보존이나 원본 읽기조차 실패하면 새 쓰기를 막는다. 기존 NFC 키·내용·로직은 변경하지 않았다.
- v1 관찰 CSV 머리글은 다음과 같이 동결했다. 서술은 별도 `schema_version,workbook_id,field,value`다. 전체 관찰 CSV에는 실제와 데모가 함께 들어가되 data_type으로 구분되며, 화면의 분석·보고서는 선택한 자료만 사용한다. 관찰/서술 두 파일을 함께 백업한다.

```text
schema_version,workbook_id,observation_id,trial,room,condition,distance_m,observation_status,rssi_dbm,channel,observed_at,ssid_alias,bssid_alias,note,data_type
```

- 장소별 유효 n·중앙값·dBm 수치의 산술평균·최소/최대·신호 못 찾음/미측정 수를 제공한다. 전부 결측인 방도 요약에서 사라지지 않는다. 막대는 중앙값을 나타내며 빈 값을 0으로 그리지 않는다. AP 별칭이 섞이면 비교 조건을 확인하도록 알린다.
- 질문·동기·가설·통제·반복 계획을 관찰 전에 적고, 해석·결론·보안·예상 밖 결과·추가 실험·방어·한계·면접을 이어서 작성한다. 서술도 CSV로 복구하며 보고서 미작성 항목을 만들어 채우지 않는다. Markdown·복사·인쇄와 표준 라이브러리 Python 코드 내려받기를 제공한다. Python은 실제 자료만 필터링해 같은 결측 규칙과 요약을 터미널에 출력하며 웹에서 실행하지 않는다.
- `/lab/`의 첫 Wi-Fi 카드만 웹 사용 가능으로 바꾸고 실제 시작 링크를 연결했다. 나머지 11개는 추후 개발 예정이다. NFC 헤더·기술노트의 관련 문구만 이 상태에 맞췄으며, 학습 6단계는 계속 NFC다. 스크립트가 없으면 절차·예시 표와 공책으로 분석/보고서를 이어 가는 질문을 읽을 수 있다.

- 13장: 미션과 생활 사례, 우리 장비와 외부 도구(이 기기에서 읽을 것과 실행 미검증 상태, 외부 도구로 할 일), 용어와 화면에서 읽는 위치, 원리(메시지, 프레임, 빛, RF, 데이터 흐름), 실험 설계(바꿀 것, 고정, 기록, 반복, 판정 기준), 한 번의 측정과 기록(입력, CSV 저장과 복구), 골든 데이터와 예상 분석값, 분석(입력, CSV, 분석, 그래프, 결론), Colab, 문제 해결, 위협과 방어(성립 조건과 영향, 방어, 근거와 한계), 현업 응용과 확장 프로젝트(입력, 처리, 출력, 부품과 도구, MVP, 확인 기준, 한계), 보고서와 평가.
- 서술 9항목(질문, 가설, 고정 조건, 해석, 결론, 위협과 방어, 한계, 응용, 1분 설명)마다 주제별 작성 예시와 이렇게 쓰는 이유를 접어서 보여 준다. 입력란에 넣기는 별도 버튼이며 이미 쓴 칸은 확인 없이 덮어쓰지 않는다.
- 보고서는 학생 서술, 지금 보는 구분(실제 또는 데모)의 원자료, 계산 결과로 만들어 미리보기와 Markdown 다운로드로 제공한다. 미작성은 (미작성), 결측과 미확인은 그대로 둔다.
- 골든 데이터 하나에서 페이지 표, 브라우저 계산(`summaryRows`, `wifiSummaryRows`, `csvSummary`), Colab 예시 CSV를 만들고, `scripts/check-workbooks.ts`가 Colab 실행 결과(JSON)와 브라우저 계산을 대조한다.
